0结论先行

产品已定为全年四季通用款。季节（春 4–5 月 / 夏 6–8 月 / 秋 9–10 月 / 冬 11–3 月）是贯穿全局的一级维度：穿衣与装备、当季线路、错峰建议、目的地与吃喝推荐全部随季节切换。国庆只是五个出行档期之一，不再作为产品的时间边界。

首选形态：微信小程序（原生 + 云开发），配套一个 H5 分享页用于非微信渠道传播。

理由是场景匹配度：目标用户是「朋友结伴 / 情侣」的小团组，行程要发给同伴、要 AA 记账、要在景区现场临时改路线——这些动作全发生在微信会话里，小程序的分享卡片、群待办、服务通知是天然入口，H5 和原生 App 都要额外付出传播成本。

AI 不做噱头，只嵌三处刚需：① 行程生成与临时变更（规划 Agent）；② 交通询价与防宰客核验（价格顾问 RAG）；③ 本地小馆推荐（去网红化检索）。三处都有明确兜底规则，宁可说"暂无可靠参考"，绝不编造价格和开放时间。

本期坚决不做交易闭环（不代订门票、不组织包车、不收佣）——这是规避《旅行社业务经营许可证》和资金合规的关键取舍，详见第 11 节。

1业务目标与成功指标

维度定义
一句话定位东北全年四季通用的小团组（2–7 人）旅行管家：行前准备 + 行中变更 + 行后复盘，狍坨坨 & 狍果果担任 IP 引导员。
要解决的核心问题① 出发前不知道带什么、怎么排、会不会被宰；② 旅途中一堵车、一变天、一闭园就全盘乱套；③ 回家只剩一堆照片，说不清钱花在哪、下次该怎么改。
北极星指标行程「一次采纳率」：AI 生成的行程在用户手动修改 ≤2 处后即被采纳的比例，MVP 目标 ≥60%。
辅助指标行程创建完成率 ≥75%；记账渗透率 ≥50%；次日留存 ≥35%；分享率 ≥40%；价格查询命中率 ≥85%；四季内容覆盖度 100%（每季 ≥2 条线路、≥8 个目的地、≥6 个当季吃喝）。
反向指标AI 价格幻觉投诉 = 0 容忍（一旦出现即降级为"仅展示人工审核价"）；行程生成 P90 延迟 ≤8s。
验证方式：MVP 上线后投放 100 名真实用户（东北目的地游客 + 本地居民各半），一周内回收问卷 + 后台行为数据，用「一次采纳率」决定是否投入第二期。

2目标用户与场景

👯 A 类 · 朋友结伴（3–7 人）

异地同学 / 同事组队，诉求是"谁也别寒碜、谁也别多掏"。痛点集中在：人数一多交通方案就变复杂、AA 记账扯不清、意见不统一导致行程反复改。核心功能诉求：组队共享行程 + AA 记账 + 按人数的交通方案。

💞 B 类 · 情侣 / 双人（2 人）

追求"人少、好看、别踩坑"。痛点集中在：网红点排队两小时体验为零、被出租车绕路影响心情、想找有氛围的小馆。核心功能诉求：小众点推荐 + 防宰客价格 + 本地小馆。

使用环境高度一致：行前在手机上看、行中在景区现场弱网甚至无网时看。因此离线可用是硬要求——行程、清单、已缓存的价格基准必须能离线打开。

3MVP 边界：做什么、不做什么

优先级功能说明与验收标准
P0 必须有季节切换（一级维度）全局季节选择器，联动穿衣建议、装备清单、当季线路、目的地筛选、吃喝推荐、价格季节系数。验收：切换无刷新卡顿，四套内容各自完整无缺口。
P0 必须有行程规划（AI 生成 + 手动编辑）输入：出发城市 / 日期 / 天数 / 人数 / 偏好（自然风光·人文·美食·强度）→ 输出逐日行程，可增删改顺序、标记完成。验收：生成成功率 ≥99%，可编辑无卡顿。
P0住宿算价（星级 × 档期溢价）按目的地类型（省会四城 / 其他地级市 / 景区型）× 住宿档次（经济·舒适·高档·豪华）给出平日基准区间，再乘档期溢价系数：平日周末 ×1.15、清明五一 ×1.4、暑期 ×1.35、十一 ×1.7、元旦寒假春节 ×1.9；景区型目的地冬季再叠加 ×1.35（雪乡春节实际可达基准 2.5–3 倍），大连暑期再叠加 ×1.2。输出间夜价 + 人均（按人数分摊房间数）+ 整程预估。验收：6 类目的地 × 4 档 × 5 档期全覆盖，基准可后台调参不发版。
P0错峰与拥堵规避（五档期模型）档期：平日周末 / 清明五一 / 暑期 / 十一 / 元旦寒假春节，逐档期给出拥堵等级、出发与返程窗口、入园时间、住宿涨幅。验收：5 档期 × 4 季可组合，覆盖全年日历。
P0交通算价引擎（规则计算，非拍脑袋）按人数（1–8）推荐交通方式与车型；双层定价：① 规则层——地铁按各市里程分段票价表、出租车按官方运价规则（起步价 + 续程 + 空驶/返空费 + 夜间加成 + 低速等候）实时计算；② 基准层——包车、专线、景区接驳等无公开规则的路线走人工审核库。输出：地铁 / 公交 / 出租车 / 网约车 / 机场巴士 五种方式的价格区间 + 人均 + 防宰红线（估算上限 ×1.3）。验收：黑吉辽 ≥12 城计价规则入库且可复算；规则层命中率 ≥90%，基准层 ≥80 条含更新时间与季节标记；冬季（11–3 月）标注雪地胎/四驱与上浮 10–20% 系数。
P0行前清单（按季节）四季四套装备模板 + 通用必备 + 自定义项，可勾选、可共享。验收：切换季节后清单同步换，勾选状态本地与云端双写，弱网不丢。
P0预算记账 + AA 分摊七分类记账、预算进度条、按人均/按成员分摊。验收：分摊结果与总额误差 = 0。
P0组队共享微信分享卡片邀请同伴进同一行程，成员可见可改（冲突以最后写入为准，保留 24h 操作日志）。
P1 应该有小众目的地库（带季节标签）16–24 个东北小众点，每个标注适用季节，含怎么去、住哪、票价、最佳时段、避坑提示；支持按当前季节筛选与"查看全部"。
P1本地小馆推荐（带季节）按城市 + 品类 + 季节检索（如冬季冻梨、春秋开江鱼、夏秋菌子宴），标注人均价与"本地人指引"，排除网红店标签。
P1打卡记录预设点位 + 自定义，打卡后可回填照片与一句话感受。
P1行后复盘花费结构、打卡完成率、评分、难忘瞬间，一键生成可分享长图。
P2 可以有众包价格上报与纠偏用户上报实际成交价，进入待审池，审核后入基准库。
P2天气联动的自动备选接入天气 API，按季节触发不同备选：夏季暴雨落石、冬季暴雪封路与极寒，自动推送当日室内备选方案。
本期不做交易闭环不代订门票、不组织包车、不收佣、不做商家入驻 —— 规避旅行社业务经营许可与资金风险。

4产品形态选型

形态优势劣势结论
微信小程序分享卡片直达同伴；微信登录零门槛；群场景天然契合；位置/地图能力合规可用；审核链路清晰受平台类目与审核约束；不能做虚拟支付以外的部分能力；离线能力弱于原生✅ 首选
H5 / PWA跨平台、可被搜索引擎收录、可脱离微信传播；已有原型可直接演进传播依赖链接；无法调用微信分享与通知；留存弱⚠️ 配套：做分享落地页 + 非微信渠道
原生 / 跨端 App离线能力强、可常驻安装成本高、双端审核与维护成本翻倍❌ 本期不做
纯对话式 AI 应用输入自由、处理长尾问题结构化行程难以编辑与共享；结果不稳定❌ 不做主体，作为内嵌能力
切换条件：若 3 个月内出现「非微信渠道流量占比 >40%」或「用户强烈要求离线全功能」，再评估 H5/PWA 独立化或跨端 App。

8AI 能力设计（三处刚需，不做噱头）

🗺️ 能力一：规划 Agent

输入：城市、日期（据此推导 season）、天数、人数、偏好、必去点、住宿位置、档期。
工具：POI 库检索、错峰规则表、天气查询、路线耗时（位置服务）。
输出：逐日行程 JSON（含每点建议停留、交通方式、雨天备选）。
回退：工具失败或结果不足 → 返回模板线路并标注"数据不足，已按经验线路生成"。

💰 能力二：价格顾问（规则计算优先 + RAG 兜底）

第一层 · 规则计算（优先，不经过模型）：命中 fare_rule 的城市与里程 → 按官方票价表与运价规则直接算出地铁 / 出租车 / 网约车区间，模型不参与数值生成，只做结果解释。
第二层 · 审核库检索（RAG）：包车、专线、景区接驳等无公开规则的路线，仅检索人工审核过的 price_bench 与采纳的众包上报。
输出：区间 + 计价过程（起步价/续程/空驶费逐项可展开）+ 数据来源 + 生效日期 + 防宰红线。
硬规则：两层都没有的路线，必须拒答（"暂无可靠参考，建议……"），禁止估算或编造价格；模型不得输出任何未经规则或审核库产生的数字。
回退：拒答时给出可行动建议（打表、走正规乘降点、拨 12328）。

🍲 能力三：本地味蕾推荐

从 POI 库按城市 + 品类检索，排序权重：本地人光顾信号 > 开业年限 > 人均价合理性 > 距离；主动降权网红标签与景区门口店铺。输出必带"本地人指引"一句（如"找手写菜单、居民区里的家常菜馆"）。无数据时不硬凑，返回"该城此品类暂无可靠推荐"。

18V2.6 增补：发布托管与备案路线（已实测）

国内可达性实测（2026-09-20，本机国内网络、绕过代理）：

平台实测判定
WorkBuddy 托管（当前线上）200 · 508–581ms，内容校验全中可用，首选
GitHub Pages（*.github.io）226ms 快速失败国内不可达
Cloudflare Pages（*.pages.dev）670ms 失败国内不可达
Netlify / Vercel594 / 578ms 通通但波动大，不可作唯一入口
EdgeOne 国际站750ms 通可达（境外节点）

纠正：「GitHub Pages 作正式地址」「EdgeOne 不备案也能国内快」两条均不成立。EdgeOne 默认域名在大陆只能靠 3 小时有效期的预览链接访问，不可分享；不备案只能选境外节点。

三阶段路线：① 测试/参赛用现托管链接 + 单文件 HTML 离线分发（零准备）；② 正式公开地址 = 注册域名（¥70–90/年，不要买 .cn，不备案无法解析）+ EdgeOne 国际站（免备案、免费套餐）；③ 国内极速需 ICP 备案，建议暂缓。

为什么先别备案：① 最终形态是微信小程序，小程序走云开发不需要 ICP 域名备案，只需「小程序备案」（微信公众平台提交）；② 个人备案站点不得含会员注册/在线交易/支付/企业商业宣传，将来商业化需推翻重来；③ 备案是长期合规负债，还需在开通后 30 日内办公安联网备案。若确定长期做独立 Web 品牌站再办：周期 5–19 个工作日，官方免费，域名实名认证须与备案主体完全一致（最常见驳回原因）。CloudBase 个人版及以上环境可直接作为备案云资源，无需额外购买服务器（需剩余有效期 ≥6 个月且已开启云托管固定 IP）——与小程序后端复用同一环境。

GitHub 仍建议建立仓库，但仅作版本管理与备份，不作为访问入口。

19V2.6 增补：无账号方案 · 分享链接 / 备份文件 / 微信 H5

决策：MVP 不做注册登录。三条理由：① 个人备案站点不得含会员注册/在线交易/支付接口，加账号等于自断备案路；② 成本跳变（后端+数据库+短信+隐私合规，约 +1–1.5 万 / +2 周）；③ 注册墙会在价值被感知前制造流失。

替代方案（已实装，半个工作日、零后端）：

  • 分享链接：把当前状态（季节/人数/预算/账目/清单/规划结果）打包为 JSON → Base64 → 写入 URL 的 #p= 锚点。对方点开即解析，弹出「有人给你分享了一份行程」收件箱，可选「载入这份 / 我自己规划」。载入后自动同步天数、目的地、预算、季节与人数。
  • 导出 / 导入备份：一键导出 .json 文件，换设备导入还原。微信内置浏览器不支持下载，界面已明确提示改用系统浏览器。
  • 二维码：链接生成后同步出码（api.qrserver.com，实测国内 743ms 可达），便于线下/群内扫码。
  • 微信 H5 分享：已配 og:title / og:description / og:image（狍坨坨母版图），微信内转发显示标题+缩略图；界面内提示「点右上角 ··· → 发送给朋友」。
为什么这样够用：本应用 90% 的价值是单机可完成的（规划、算价、清单、记账）。唯一真正需要账号的场景是「组队共享 / AA 同步」——那正是做小程序时用微信一键登录（wx.login 拿 openid）顺带解决的，用户无感知、无密码、无短信费、无个人信息持有责任。Web 独立账号（手机号+验证码+隐私政策+注销入口）只在确定长期做独立 Web 品牌站时才值得做。
